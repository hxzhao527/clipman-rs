# clipman-rs 已知问题

> 更新日期：2026-10-27  
> 状态：`KI-001` 至 `KI-004` 均已修复

## 处理原则

- 当前阶段优先完成主要功能、i18n 和兼容性验证。
- 下列问题已确认存在或已明确期望，但暂不阻塞主线开发。
- 修复时先补充复现条件和验收标准，避免只做表面修补。

## KI-001：全部记录窗口标题栏不稳定

| 项目 | 内容 |
|---|---|
| 状态 | 已修复 |
| 优先级 | 中 |
| 发现日期 | 2026-10-27 |
| 影响范围 | “全部记录”GTK 窗口 |

### 现象

同一个“全部记录”窗口有时显示包含最大化、最小化和关闭按钮的标题栏，有时不显示这些窗口装饰。

### 期望

窗口装饰需要在同一会话、重复打开和关闭、不同启动顺序下保持一致。

### 待确认

- 是否只发生在窗口隐藏后重新显示时；
- 是否与 Waybar/labwc 当前焦点或窗口规则有关；
- 最终统一使用 GTK client-side decoration，还是依赖 compositor 的 server-side decoration；
- 设置窗口是否需要与历史窗口采用相同的装饰策略。

### 修复时机

主要功能完成后，与 GTK 窗口规范化和主题检查一起处理。

### 修复结果

“全部记录”和“配置”窗口统一显式设置 GTK `HeaderBar`，使用稳定的 client-side decoration，不再依赖 compositor 是否提供标题栏。已在 labwc 下同时打开两个窗口验证。

## KI-002：托盘菜单缺少空历史占位项

| 项目 | 内容 |
|---|---|
| 状态 | 已修复 |
| 优先级 | 低 |
| 发现日期 | 2026-10-27 |
| 影响范围 | 托盘弹出菜单 |

### 现象

普通历史为空时，托盘菜单的普通历史区域没有任何内容，直接显示后续控制项，用户无法直观确认当前只是没有记录，还是菜单加载异常。

### 期望

当普通历史为空时，在托盘菜单的普通历史区域显示一个不可点击的“暂无记录”条目。

### 修复时机

与托盘菜单最终视觉和空状态统一处理。

### 修复结果

普通历史为空时，菜单会显示 `enabled = false` 的“暂无记录”条目。存在 Primary 但没有普通历史时同样显示该占位项。

## KI-003：源应用退出后普通剪贴板内容不可粘贴

| 项目 | 内容 |
|---|---|
| 状态 | 已修复 |
| 优先级 | 高 |
| 发现日期 | 2026-10-27 |
| 影响范围 | 普通剪贴板文本 |

### 复现步骤

1. 启动 clipman-rs 和程序 A。
2. 在程序 A 中复制一段文本。
3. 确认托盘菜单中出现该记录。
4. 关闭程序 A。
5. 切换到程序 B，不打开托盘菜单，直接执行 `Ctrl+V`。

### 当前结果

程序 B 不能粘贴刚复制的内容。

随后点击托盘菜单并选择该历史条目，内容会重新写入普通剪贴板，此时程序 B 可以正常粘贴。

### 期望

只要文本已被成功捕获并写入历史，即使源应用 A 随后退出，程序 B 仍应能直接粘贴该文本，不需要用户先打开托盘菜单并重新选择记录。

### 可能原因

Wayland 中剪贴板数据由源应用持有。当前实现只把 MIME 内容读取并保存到 SQLite，没有在捕获完成后接管普通剪贴板数据源。源应用 A 退出后，compositor 失去数据源，普通剪贴板变成空；用户从托盘选择记录后，clipman-rs 才通过 `copy_multi` 成为新的数据源，所以粘贴恢复。

### 修复方向

- 捕获提交成功后，考虑由 clipman-rs 重新提供保存的完整 `text/*` 集合并接管普通剪贴板；
- 继续使用 fingerprint 抑制自身写入事件，避免循环记录；
- 验证接管时机：立即接管，或在 source 清除事件后接管；
- 验证接管后目标应用可继续读取全部已保存 MIME；
- 验证重复复制、快速连续复制和程序退出语义。

### 修复时机

应优先于 i18n 等非核心完善工作处理，因为它影响剪贴板管理器的核心可靠性。

### 修复结果

捕获普通文本后会保留最近一次 payload。源应用退出导致 selection cleared 时，clipman-rs 自动通过 `copy_multi` 接管普通剪贴板，并利用 fingerprint 抑制自身事件。已实测关闭 `wl-copy` 源进程后仍可直接读取文本。

## KI-004：清空历史后当前剪贴板仍可粘贴

| 项目 | 内容 |
|---|---|
| 状态 | 已修复 |
| 优先级 | 高 |
| 发现日期 | 2026-10-27 |
| 影响范围 | 普通历史清空和普通剪贴板 |

### 复现步骤

1. 复制一段文本，确认它进入普通历史。
2. 从托盘菜单或“全部记录”窗口清空普通历史。
3. 切换到任意文本输入位置执行 `Ctrl+V`。

### 当前结果

普通历史虽然被清空，但当前普通剪贴板仍保留清空前的数据，因此仍能粘贴成功。

### 期望

两个清空入口都应在清除普通历史的同时清除当前普通剪贴板。清空完成后执行 `Ctrl+V` 不应再取得已清除的内容。

普通历史清空不删除 Primary Selection。

### 可能原因

当前清空操作只删除 SQLite 中的普通历史记录，没有通过 data-control 设置空普通剪贴板 selection。

### 修复方向

- StorageActor 清空普通历史成功后，由 ClipboardService 清除普通剪贴板；
- 托盘入口直接执行；
- 全部记录窗口入口在用户确认后执行；
- 清除操作不删除 Primary；
- 验证清除后 watcher 不会把 selection cleared 事件重新记录为历史。

### 修复结果

两个普通历史清空入口现在都会：

1. 删除 SQLite 普通历史；
2. 清除 ClipboardService 保存的最后一个普通 payload；
3. 通过 data-control 清除普通剪贴板 selection；
4. 阻止 cleared 事件触发内容回填。

已实测清空后普通剪贴板返回空，菜单显示“暂无记录”。
